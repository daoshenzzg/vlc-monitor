## ✨ 核心特性

- 🎯 **多区域独立 ROI 圈选**
  - 在视频画面中任意拖拽划定监控小窗，每个区域独立命名、独立配置检测开关与灵敏度阈值。
  - 完美契合导播多画面分割器（Multiviewer / 画面分割墙）的分布式盯盘需求。
- ⚡ **零拷贝超轻量架构**
  - 直接接入 libVLC 内部渲染内存回调，无额外 FFmpeg 进程，无二次推拉流与重编码开销。
  - 极低 CPU 与内存占用，老旧工控机或办公轻薄本均可长时间稳定运行。
- 🔍 **智能双模异常检测**
  - **黑屏检测**：像素亮度智能统计，精确识别切流黑场与信号丢失。
  - **静帧检测**：自适应基线比对，有效容忍画面微小抖动，支持针对静态台标/节目单独立关闭静帧比对。
- 🔔 **多级防骚扰告警系统**
  - **本地强提醒**：异常区域高亮红框标记、系统前台请求召回、定制警报蜂鸣、周期性未确认循环提醒，支持 5 分钟临时一键静音。
  - **微信实时通知**：同一次故障**仅推送首发告警**，持续故障期间静默不轰炸；画面恢复正常时自动发送**恢复通知**，形成完整值守闭环。
- 🛡️ **安全私密与开箱即用**
  - 零云端依赖，本地 SQLite 数据库独立记录全部告警与恢复事件。
  - 微信通知凭证直接交由系统底层安全库（macOS Keychain / Windows 凭据管理器）加密托管，无明文泄露风险。

## 🎯 典型应用场景

### 1. 演播厅 / 云导播多画面大屏（Multiviewer）值守
在现场直播或大型活动中，云导播通常会输出一路包含多机位的拼接多画面信号（如 4 分屏、9 分屏、16~20 分屏 Multiviewer 画面墙，包含机位源、延时前后画面及 PGM 主输出）。使用 VLC 监播工具，可在同一窗口内为关键机位分别划定独立 ROI，实现全自动盯盘：

```text
┌────────────────────────────────────────────────────────┐
│  云导播 / 演播室 多画面监视大屏 (Multiviewer 拼接流)   │
├──────────────┬──────────────┬──────────────┬───────────┤
│ ┌──────────┐ │ ┌──────────┐ │ ┌──────────┐ │ ┌───────┐ │
│ │ 1号机(主)│ │ │ 2号机(特)│ │ │ 3号机(全)│ │ │ 4号机 │ │
│ └──────────┘ │ └──────────┘ │ └──────────┘ │ └───────┘ │
│  [ROI-1 监播]│  [ROI-2 监播]│  [ROI-3 监播]│           │
├──────────────┼──────────────┼──────────────┼───────────┤
│ ┌──────────┐ │ ┌──────────┐ │ ┌──────────┐ │ ┌───────┐ │
│ │ 延时播出 │ │ │ 备路信号 │ │ │ PGM 主输出│ │ │ 包装条│ │
│ └──────────┘ │ └──────────┘ │ └──────────┘ │ └───────┘ │
│  [ROI-4 监播]│              │  [ROI-5 监播]│ (已避开)  │
└──────────────┴──────────────┴──────────────┴───────────┘
```

- **独立阈值控制**：各机位根据画面动态特征（如演播机位 vs 静态包装台标）配置差异化灵敏度。
- **单路流超低开销**：单路 1080p/4K 导播多画面信号只需解码一次，后台共享帧缓冲直接执行轻量 ROI 裁剪与比对，资源开销不随区域数量线性激增。

### 2. 直播推流与转码分发链路巡检
支持监听 RTMP、RTSP、UDP、HTTP(S) 及本地排练视频。在推流节点或 CDN 边缘节点拉流监测，第一时间捕获网络抖动造成的黑屏停流或解码卡顿。

## 🚀 4 步快速上手

```text
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  1. 打开视频/流  │ ──> │  2. 圈选监控区域  │ ──> │  3. 设定判定规则  │ ──> │  4. 开启实时监播  │
│ 本地文件 / 网络流 │     │ 自由框选 / 缩放  │     │ 阈值与连续次数   │     │ 本地声光 + 微信 │
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
```

1. **打开视频源**：
   - 在顶部地址栏输入直播流地址（如 `rtmp://...`、`rtsp://...`、`udp://...`），或点击文件夹图标选择本地视频文件（支持快捷键 `⌘O` / `Ctrl+O`），点击 **“播放”**。
2. **圈选监控区域**：
   - 点击 **“＋ 新增区域”**，在视频画面中按住鼠标左键拖动圈出关注区域（按 `Esc` 取消）。
   - 选中区域框可整体拖动，拖动右下角控制手柄可调整尺寸；建议单机位画面独立成框，避开滚动字幕与演播室时钟。
3. **配置检测规则**：
   - 在右侧面板中自定义区域名称，勾选需要的“黑屏”或“疑似静帧”检测，设置**连续检测次数**（触发告警门槛）与**恢复连续次数**（判定恢复门槛），点击 **“应用规则”**。
4. **开始监播**：
   - 点击 **“开始监播”**。发生异常时出现红框与声音警报；若需离开工位，可在“设置”中配置微信通知；点击主界面 **“保存配置”** 即可在下次启动时一键还原区域与规则。

> [!TIP]
> **确认告警 vs 恢复正常**：点击“确认当前告警”仅停止当前批次事件的刺耳声音提醒，画面红框仍会持续指示异常；只有画面恢复动态达到设定次数后，系统才会标记为“恢复正常”。

| 平台 | 构建架构 | 系统要求 | 安装形式 |
| :--- | :--- | :--- | :--- |
| **macOS** | Apple Silicon (ARM64) | macOS 13.0+ | 双击运行 `.app` (无须 Python) |
| **Windows** | x64 (64位) | Windows 10 / 11 | 解压目录运行 `VLCMonitor.exe` |

### 依赖说明
本工具采用**外置轻量级绑定架构**：
- **终端用户无需安装 Python 环境**。
- 运行前电脑需安装同架构的官方完整版 **[VLC 播放器](https://www.videolan.org/vlc/)**（Mac 安装 Apple Silicon 版本，Windows 安装 64 位版本）。本工具启动时会自动探测系统 VLC 路径，不私自打包或修改系统 libVLC。

### 获取安装包
- **稳定正式版**：前往 [Releases](https://github.com/daoshenzzg/vlc-monitor/releases) 页面下载对应系统的压缩包与 SHA256 校验文件。
- **最新尝鲜版**：前往 GitHub [Actions](https://github.com/daoshenzzg/vlc-monitor/actions) 页面，选择最近一次成功的构建流水线，在 **Artifacts** 中下载对应平台的构建包。

## ❓ 常见问题 (FAQ)

<details>
<summary><strong>Q1: 为什么需要单独安装官方 VLC，而不是软件直接内置捆绑？</strong></summary>

> 本工具遵循 VLC (LGPL/GPL) 开源合规要求，并最大化复用本机硬件加速与完整解码插件生态。通过动态链接本机已有 VLC，既保证了极小的安装包体积，又能避免内置旧版解码库带来的安全与兼容性隐患。
</details>

<details>
<summary><strong>Q2: 画面本身就是静态图片或倒计时，会误触发静帧告警吗？</strong></summary>

> 1. **圈选规避**：划框时建议避开数字时钟、静态台标或滚动字幕条；
> 2. **关闭静帧**：如果该机位本身播放的就是静态节目单或排练彩条，可在右侧“区域规则”中取消勾选“疑似静帧检测”，仅保留“黑屏检测”；
> 3. **调节判定帧数**：适当调大“静帧比较次数”，提高静帧触发的容忍时长。
</details>

<details>
<summary><strong>Q3: 微信通知需要自己搭建服务器或申请公众号/企业微信吗？</strong></summary>

> 完全不需要。本工具内建轻量化微信通知集成，在“设置 ➔ 微信通知”中直接扫码授权即可。异常首次发生时提醒，持续故障不轰炸，恢复时自动闭环。凭据直接保存在系统底层 Keychain / 凭据管理器，退出软件绝不驻留任何后台进程。
</details>

<details>
<summary><strong>Q4: 为什么更换播放流地址后，需要重新点击“开始监播”？</strong></summary>

> 为了确保监播准确性，切换视频源后分辨率、帧率及画面比例可能发生变化，系统会主动重置基线帧并暂停监播，方便操作人员复核原有区域是否依然准确匹配画面。
</details>

## 🛠️ 开发者指南

本项目使用 Python 3.12 与 [uv](https://github.com/astral-sh/uv) 进行工程管理。

```bash
# 1. 克隆代码并安装依赖
git clone git@github.com:daoshenzzg/vlc-monitor.git
cd vlc-monitor
uv sync --locked --extra dev

# 2. 本地直接运行
uv run --no-sync vlc-monitor

# 3. 运行离线单元测试
QT_QPA_PLATFORM=offscreen uv run --no-sync pytest -q

# 4. 安全扫描与交付合规审计
uv run --no-sync python tools/delivery.py audit
uv run --no-sync python tools/delivery.py scan

# 5. 跨平台打包
# macOS (ARM64)
sh packaging/build-macos.sh
# Windows (x64 PowerShell)
pwsh -File packaging/build-windows.ps1
```
