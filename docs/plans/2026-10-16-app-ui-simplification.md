# VLC 监播工具：全 App 极简 UI 实施计划

日期：2026-10-16  
状态：已实施并完成离屏核验；用户已确认第二版实际 Qt 预览，按原视觉与轻量入口落地。执行证据与实机待验边界见 [实施记录](2026-10-16-implementation.md)。

执行修订：用户指出右上角按钮过多且密集，确认采用顶栏轻量设置/保存、输入框内本地文件入口、底部静音和区域标题旁轻量新增；不再机械保留六个等重按钮。微信周期重复提醒以稳定性计划为准，全部移除。  
目标项目：当前工作目录下的 `vlc-monitor/`；后续所有实现集中到该独立项目。  
关联计划：[独立项目迁移与 GitHub 自动打包](2026-10-16-github-delivery.md)。

## 1. 目标、依据与范围

**范围是整个 App，不只是微信弹窗。** 用户期望“UI 大道至简，简单好用”，不是重新换肤，也不是把杂乱按钮全部藏进“更多”。

日常路径收敛为：**输入视频来源 → 播放 → 框选区域 → 开始监播**。复用已工作的播放、检测和微信能力，优先精简信息、操作入口和交互层级。

### 1.1 已知事实

- 当前源码基线为 `0.3.0`；前一任务正在收尾，正式迁移前必须再确认文件基线，不能沿用早先 `0.2.0` 的清单。
- 用户已经确认微信基础收发和真实告警发送测试通过。不得再将其写成“微信尚未验证”，也不要求用户重新扫码验证正常绑定。
- 手机恢复通知、所有断网/重启分支和长期稳定性不能从“告警已收到”推导为全部通过；这些记录放交付文档，不常驻主界面。
- 用户提供的三张截图是需要改进的当前界面，不是目标设计；旧 `docs/mac-ui-current.png` 也不是本次目标，且含个人路径，不直接用于公开 README。
- 已委派代码交互审查、微信生命周期审查，以及产品交互/UI 设计审阅；本计划采用六按钮主窗口方案，不采用早期仍保留重连按钮和设置下拉的建议。

### 1.2 覆盖的界面

1. 主窗口标题、地址输入、播放、监播控制和运行状态。
2. 视频画布、区域创建/编辑、阈值、撤销与删除。
3. 告警条、临时静音、确认告警和历史记录。
4. 常规设置、本地提醒测试和微信通知。
5. VLC 缺失/路径选择、连接错误、配置错误和退出确认。
6. 后续 GitHub README 的真实界面截图、功能与操作说明。

### 1.3 明确不做

- 不重写检测引擎、微信协议、队列、凭证库或播放器线程。
- 不引入网页框架、全新主题、动画体系、托盘常驻、自动播放/监播、自动登录或无限重试。
- 不把监播次数阈值改成秒；不改变确认、静音、恢复、手动停止的业务含义。
- 不为了减少按钮而自动保存、自动切源、跳过本人绑定确认或移除取消/停止路径。
- 不在本轮增加 Linux、Intel Mac 或 Windows ARM 支持。

## 2. 全 App 设计规则

- 沿用浅灰底、深蓝文字、橙色主操作和现有平台字体；只调层级、留白、排列和文案。
- 主任务可见，低频配置进入具名设置页；不再使用“更多”、单项下拉或多级操作菜单。
- 正常状态短句表达，异常给出原因和下一步；去掉实现细节、长免责声明、静态示例大段文字。
- 不适用的步骤隐藏；当前操作正在执行时保留原位并禁用，避免按钮跳动导致误点。
- 状态不能只靠颜色区分；危险动作不是默认回车动作。
- 应用规则、立即生效、保存到磁盘三种行为必须区分，不以“取消设置”暗示能撤回微信已发请求。

## 3. 主窗口：六个全局按钮

```text
VLC 监播                                     [设置] [保存配置 *]

视频来源 [地址或本地路径__________________] [本地视频] [播放]
          （仅在必要时显示连接错误或新地址尚未生效）

[开始监播]                                     [静音 5 分钟]

┌ 视频画面与监播框 ─────────────────┬ 监播区域       [新增区域] ┐
│                                  │ 区域列表                  │
│                                  │ 名称、启用、检测类型      │
│                                  │ 检测与恢复次数            │
│                                  │ [应用] [取消]      [删除] │
└──────────────────────────────────┴───────────────────────────┘

（有异常时）2 项异常，1 项未确认                   [确认告警]

告警与恢复
时间 | 区域 | 类型 | 命中/经过 | 状态 | 通知

播放中 · 监播中 · 声音开启 · 微信通知已开启
```

六个全局按钮：**设置、保存配置、本地视频、播放/停止播放、开始/停止监播、静音/取消静音**。区域编辑及有告警时的确认动作不计入全局按钮数；不能用数量指标删掉必要安全操作。

### 3.1 入口取舍表

| 当前入口 | 处理 | 新位置/行为 |
| --- | --- | --- |
| 设置 / 更多下拉 | 删除 | 单个“设置”按钮，直接打开设置窗口 |
| 播放下拉、单独重连 | 删除 | 停止播放后再播放；不另加重连按钮 |
| 主界面声音复选框 | 移动 | 设置 → 常规 → 告警声音；主界面仍显示声音状态 |
| 主界面测试告警 | 移动 | 设置 → 常规，单个测试入口 |
| 菜单中 5 秒后测试 | 合并 | 同一测试入口可选择立即/5 秒后 |
| 全局新增区域 | 移动 | 区域面板标题旁 |
| 保存配置 | 保留 | 短文案、固定位置，未保存显示 `*`，不改成自动保存 |
| 静音 5 分钟 | 保留 | 随状态变为取消静音；不会影响微信 |
| 微信独立大按钮 | 不新增 | 设置 → 微信通知；底部显示状态 |
| 诊断、脱敏导出、VLC 路径 | 移动 | 设置 → 常规 → 播放器与支持，非主窗口工具栏 |

### 3.2 播放与换源状态合同

| 状态 | 唯一播放按钮 | 约束 |
| --- | --- | --- |
| 未连接 | 播放 | 使用当前输入；空输入就在输入处提示 |
| 正在连接 | 取消连接 | 发取消请求，不创建第二播放器 |
| 正在取消/停止 | 正在取消/正在停止 | 禁止重复连接，等待真实完成 |
| 正在播放 | 停止播放 | 结束播放及当前监播；不将其改成暂停 |
| 播放失败 | 重试播放 | 仍沿用唯一入口 |
| 释放失败 | 重试停止 | 完成清理前禁止启动新播放器 |

- 去掉独立重连后，重连同源或换源统一为“停止播放 → 播放”；重新播放后必须手动开始监播。
- 播放中编辑地址不自动切源；显示“新地址将在停止后播放”。当前播放源和输入草稿不得混为一谈。
- 回车不能绕过停止阶段或静默切源；仅在未连接/可重试状态触发播放。
- 保留当前停止操作的即时语义，不新增每次停止都弹确认的干扰；按钮提示明确“停止播放也会停止监播”。
- 长地址在输入框内滚动，不撑开布局；不得把完整地址复制到日志、错误详情或截图。

## 4. 区域面板、告警与历史

### 4.1 区域创建与编辑

- 无区域时，只显示“新增区域后，在画面中拖出检测框”；不展示整块无效表单。
- 选中区域后显示名称、启用、黑屏/疑似静帧、连续次数与恢复次数。保留次数单位和默认值，不新增高级参数。
- 新增区域入口与区域列表放在一起；框选时显示“拖动框选，Esc 取消”。Esc 的现有行为需核查，缺失则仅补 UI 取消路径。
- 选中区域时“应用/取消/删除”位置固定；没有草稿时应用/取消禁用，不能为减少按钮丢失撤销路径。
- 删除与应用拉开间距；保留既有历史，不增加清空历史的连带行为。
- 将常驻三行操作说明缩为一行，详细说明放 README；滚动字幕会干扰判断等关键提示可用字段 tooltip。
- 不将已应用规则与磁盘保存混用：应用影响当前区域，保存配置才保留到下次启动。

### 4.2 告警条与声音

- 告警出现才显示告警条，不留空白占位；摘要最多约两行，长名称不得挤走确认按钮。
- “确认告警”只停止该批事件强提醒，不把异常标为恢复，也不停止微信。
- 如果全部已确认但异常仍在，保留“已确认，异常持续”的弱化提示；不能变绿或消失为正常。
- “静音 5 分钟”只影响本地声音；静音期间显示剩余状态并可取消，关闭声音时避免暗示静音按钮能重新开启声音。
- 更改上述呈现前先核对 attention/coordinator 的活动事件与待确认事件数据；若现有 snapshot 不足，只扩展只读显示数据，不改告警判定。

### 4.3 历史记录与底部状态

- 保留现有六列，只缩短标题，去掉“不逐帧写入”等实现说明；不新增搜索、筛选或历史工具栏。
- 保留“恢复正常、手动停止、监播中断”等结束原因，保留微信失败/未知/接口接受的差别。
- “接口接受”不可显示为“已送达”。详情太长可省略展示并通过 tooltip/只读详情查看，原数据不丢弃。
- 空表仅显示“暂无告警记录”；最小尺寸允许表格自身横向滚动，不允许整个窗口横向溢出。
- 底部只保留播放、监播、声音、微信状态和当前必要错误；帧序号等技术信息移至诊断。

## 5. 设置窗口：常规 / 微信通知

单个设置窗口、两个具名页签；不另加“更多/高级”菜单。共享页脚为“关闭”，而不是会暗示回滚全部即时动作的“取消设置”。

### 5.1 常规页

```text
[常规] [微信通知]

本地提醒
  告警声音                     [开关]
  新告警时显示主窗口           [开关]
  未确认告警提醒间隔           [5 秒]
  测试时机 [立即 / 5 秒后]     [测试提醒]
  （编辑后）[应用] [取消]

播放器与支持
  VLC 位置：……                [更改]
  [查看诊断]                  [导出脱敏配置]

未保存的更改需在主界面保存配置。              [关闭]
```

- 本地提醒编辑保留草稿应用/取消语义；测试默认使用已应用配置，避免用户误以为未应用草稿已生效。
- 切页或关窗遇未应用的本地草稿，仅提示处理该草稿；不可回滚已执行的微信动作。
- 合并即时/延时测试入口；文案明确“仅测试本地提醒，不发送微信”。测试本身不要求保存配置。
- VLC 路径、诊断、导出集中为一小组支持功能，不再分散为主界面按钮；保留脱敏规则。
- 修改 VLC 路径仍在下次启动生效，不热替换正在使用的 libVLC。

### 5.2 微信页常态

```text
接收微信通知                              [开关]
已绑定 · 通知已开启

最近结果：接口已接受，请核对手机          （有结果才显示）

重复提醒                                  [开关]
每 [60] 秒                                （开启重复提醒才显示）

[发送测试]                                  [解绑]

关闭设置不改变通知状态。未保存的开关需保存配置。
```

- 删除所有用户可见“试用”用语，包括标题、状态、按钮、测试消息和当前使用文档；不重命名内部 `trial_sendable` 等状态以免无谓扩大范围。
- 单个开关替代“启用/关闭”两个按钮；开关表达实际 enabled，不代表手机送达保证。
- 删除长说明、静态消息示例和空二维码占位；队列为零不显示队列行。
- 删除常驻“本人手机已收到测试”按钮：当前它不是新告警发送门槛。测试结果用短句提示人工核对手机，不新增强制收件确认流程。
- **保留绑定时“确认是本人发送”**。这与测试收件确认不是一回事，不得一起删除。

### 5.3 微信状态到操作的映射

| 状态 | 展示/操作 | 不可省略的边界 |
| --- | --- | --- |
| 已关闭 | 关闭的开关；已有绑定可解绑 | 零微信网络、零凭证读取；打开页签本身不启用 |
| 开启但未绑定 | 绑定微信 | 用户点击后才请求二维码 |
| 扫码/挑战中 | 当前步骤、二维码或挑战 | 不常驻所有步骤；开关关闭仍可停止流程 |
| 等待本人确认 | 确认是本人发送 | 保留身份匹配、有效期、显式确认 |
| 已绑定/上下文待验证 | 发送测试、解绑 | 不要求重复测试才能发送新真实告警 |
| 测试发送中 | 原位“发送中”，禁止重复点击 | 不因按钮位置变化造成误点 |
| 接口接受 | 接口已接受，请核对手机 | 不写已送达 |
| 失败/不确定 | 一句具体结果和下一步 | 不确定时先核对手机，不自动无限重试 |
| 会话失效 | 绑定已失效、解绑入口 | 删除成功后才允许重新绑定，不盲串多个异步命令 |
| 凭证删除失败 | 解绑未完成、重试解绑 | 不能重新开启，不降级明文存储 |

### 5.4 生命周期与保存不变

- 关闭微信页/设置窗口只断开视图订阅，通知服务继续归主应用所有；退出 App 才关闭服务。
- 关闭通知开关立即停止新通知并取消旧任务，保留凭证；解绑才删除系统凭证。在途请求无法撤回。
- 开关和重复提醒先改变运行态并标记未保存，仍通过主界面“保存配置”持久化。重启恢复最后保存值，不能暗示自动保存。
- 已保存开启可在重启后读取系统安全绑定；不得自动登录、自动播放、自动监播或补发旧告警。
- 刷新开关用 `QSignalBlocker` 等防反向触发；不得每次 snapshot 更新都重复执行启用/关闭。
- UI 重组须保证设置页重复打开/关闭不会重复创建服务、线程、订阅或发送。

## 6. VLC 选择、错误与退出

- VLC 缺失时保留清晰阻塞提示和“浏览/粘贴路径”两条路径；不增加多步安装向导。
- 从设置打开选择器：取消不更改路径；启动失败流程若取消意味着退出，使用“退出”文案。
- 路径错误就地显示，保留已输入内容；Mac 选择 `.app`，Windows 选择安装目录，不能把 Mac 应用包变为普通目录浏览。
- 地址、VLC 路径、微信错误尽量就地显示；成功不弹确认框。配置保存失败、解绑、危险删除、退出等必要阻断保留。
- 弹窗按钮用“解绑/删除区域/保存并退出”等具体动作，避免含糊“是/否”；危险操作不得默认获得回车焦点。
- 退出时保留“保存并退出 / 不保存退出 / 取消”；不保存只是不持久化配置，不是撤回已经发送的消息。
- 播放器释放或线程退出失败，不假装退出成功；必须保留重试和错误提示。

## 7. 视频格式与地址的准确表述

**结论：尝试播放本机安装的 VLC/libVLC 支持的媒体输入，不承诺“任何格式都可监播”。**

- 当前 `models.py` 对来源做字符串/长度校验，没有限定协议白名单；`vlc_backend.py` 直接调用 `instance.media_new(source)`。
- 可在说明中列举本地视频、HTTP(S)、RTSP、RTMP、UDP 等输入类型，但标明实际取决于本机 VLC 插件、编解码器、网络和源权限，不列为全部实测通过。
- VLC 桌面播放器能打开的内容，如果依赖额外认证交互、自定义选项或特殊插件，不代表本工具单个输入框已经覆盖。
- 监播还需持续新鲜视频帧、可用画面元数据、有效检测区域等；纯音频、旋转/镜像元数据和其他不满足当前检测条件的输入不得显示为可正常监播。
- 本轮不增加协议白名单或媒体打开功能，不改变网络/凭证处理；用实际后端返回的原因解释失败。
- 推荐输入提示：“输入视频地址，或选择本地文件”；README 补一句：“播放能力取决于本机 VLC，监播需要可读取的视频画面。”

## 8. 任务拆分与依赖

所有文件路径以新项目根目录为准。开始前先按关联计划完成 M0–M2 的基线冻结、白名单复制和基础运行核验；本轮只有计划文件，不构成已迁移项目。

| 编号 | 任务与操作 | 修改范围/唯一负责人 | 验收产出 |

## 10. 全 App 视觉验收

- 主窗口：目标默认 `1240×820`、最小 `920×640`，均为 Qt 逻辑像素；设置窗口目标常态约 `560×520`，扫码按需扩展但不超屏。
- macOS Retina、Windows 100%/150% 缩放分别检查。尚无目标环境时明确标记待验，不能用 offscreen 截图代替全部原生验证。
- 主窗口无“设置/更多”、播放下拉、重复测试入口；不是只验微信弹窗。
- 逐态检查：未连接、播放未监播、正常监播、异常未确认、已确认仍异常、区域编辑、发送失败/未知历史。
- 设置检查：常规草稿、微信关闭/未绑定/扫码/本人确认/已绑定/失败/解绑失败；无空 QR 占位和禁用按钮墙。
- 辅助窗口检查：VLC 路径错误、保存失败、未保存退出；在小窗口/高 DPI 下关闭、取消、停止和保存始终可达。
- Tab 顺序、可见焦点、Esc、Enter、防误触危险动作；长中文名、长路径、字体缩放不得盖住按钮。
- 常规文字对比度至少 4.5:1；不通过缩小全局字号强行塞下内容，不用色彩替代状态文字。
- **自动化通过不等于 UI 验收通过。U1 先看真实渲染，U7 再做完整视觉复核，用户认可后收尾。**
