# 0.4.0 实施与验收记录

日期：2026-10-16。范围为独立 `vlc-monitor/`；父目录源码、旧包和用户运行数据未改动。本文区分代码实现、本地证据与待验事项，不代替生产验收。

## 基线、决策与迁移

- 权威基线为 0.3.0：父项目完整离线回归 **136 passed**。复制 47 个审定文件，逐一比对 SHA256；源码快照和逐文件清单保留在父项目的本地 `tmp/implementation-20261016/`，不进入源码附件。
- 采用白名单复制而非移动：源码、测试、构建脚本、锁文件及必要说明；未复制用户配置、SQLite、账号/凭证、私有流、旧图片、历史诊断、外部审计副本或旧二进制。
- 所有后续实现只修改新目录。Qt 组织/应用名、bundle id、用户数据路径、配置 schema 2、SQLite 三表及凭证身份保持不变。
- 用户否定第一版 UI，并明确问题为右侧大按钮过多、过密；随后对第二版实际 Qt 预览回复“这一版满意”。采用原版视觉与分栏，顶栏轻量设置/保存、输入框内本地文件入口、底部静音、区域标题旁轻量新增，不机械保留六个等重按钮。
- 稳定性计划优先：微信只发首次和正常恢复，删除周期 repeat；本地声音周期、确认和静音不变。版本统一为 **0.4.0 内部候选**，锁文件仅更新本项目版本，没有升级第三方依赖。

## 实施结果

| 领域 | 已实现 | 验证边界 |
| --- | --- | --- |
| VLC 原生回调 | 分配/构造成功后原子提交尺寸与存储，失败返回 0；显示复制失败丢弃帧 | ctypes 故障注入，不制造真实 OOM；分辨率切换为离线核心测试，非原生动态分辨率验收 |
| 检测时钟 | 获取帧快照后读单调时钟 | 合法 1ms 竞争和真正未来帧分别覆盖，不放宽旧帧/会话校验 |
| 微信 | 入口与队列双重丢弃 update，无周期调度；首次/恢复幂等，首次失败后恢复独立机会，短暂异常合并 | 保留三次总尝试、2/8 秒退避、原始 300 秒 TTL、client_id 与 generation/run 隔离；不保证恰好一次或手机送达 |
| 容量和取消 | 正确归属队列拒绝；两层入口有界；结束控制溢出可见；邮箱尚未进队列的任务也报告取消 | 修复只清邮箱而丢取消回执的问题；重复关闭不重复报告 |
| 历史存储 | 专用线程创建/使用/关闭 SQLite；入口 1024 实际记录含在途批次，每批最多 64，批内事务、锁等 100ms、最多一次重试 | 初始化、查询、写入、确认、delivery、清理和关闭均不在 GUI；OS 级永久文件系统阻塞不由 SQLite timeout 保证可中断 |
| 存储退出 | 先停止生产者并处理最终 GUI 回执，再异步封闭/flush；失败可重试或明确放弃，仍安全关闭线程 | 播放器停止失败不提前关闭存储；启动异步回填不覆盖当前终态/确认/通知 |
| VLC 加载 | 同规范化路径缓存成功 binding，串行初始化；失败清理可安全释放的目录句柄，部分加载污染要求重启 | 同路径并发 100 次 mock 一次初始化；Windows 仍需原生实机 |
| 主窗口 | 无旧下拉与独立重连；唯一播放/取消/停止入口，回车不切源；区域应用/取消与 Esc；告警确认不伪恢复 | 源地址草稿与当前播放源分离；停止后新地址才播放，手动重新开始监播 |
| 设置 | 单个“常规 / 微信通知”窗口；本地草稿应用/取消守卫，单一立即/延时本地测试；微信单开关、分阶段操作 | 保留本人挑战确认；去除试用、收件确认按钮和 repeat 控件；关闭只解绑视图，不停服务 |
| 打包与 CI | 动态版本、原生双平台 job、固定 Python/uv/Action SHA、安全门禁、精确附件/哈希、标签匹配与双平台门禁 | workflow 本地静态验证不代表托管 Actions 或 Windows 构建成功；无远端、推送、标签或发布 |

## 已取得的证据

- 独立项目 `uv sync --locked --extra dev` 成功；Python **3.12.13**、uv **0.12.18**，导入指向新项目。
- 核心故障测试只补必要边界，复用并调整既有测试，不新建大规模测试框架。完整回归命令：`QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q`，最终为 **164 passed in 3.44s**。
- 真实临时 SQLite 第二连接持写锁：定向实验 100 事件 + 确认 + 清理 + 请求关闭，主线程提交约 **0.6ms**；存储锁等待时 **48 次 GUI timer 心跳**；释放锁并重试后 102 条待处理记录安全保存。该次观测不代表所有设备性能。
- 源码整合原生冒烟：标准库生成 Y4M 正常→黑屏→正常，真实本机 VLC **3.0.21**；实际主窗口、监播 worker、异步历史和播放停止/重连通过。最终复跑持数据库写锁期间 **322 次 GUI 心跳**，本次最大间隔 **25.1ms**；未持久化提示出现、正常恢复落库、安全关闭；凭证读取与微信网络请求均为 **0**（假 store/transport）。结果保存在忽略的 `tmp/controlled-smoke/report.json`。
- 另做三轮本地生成视频的原生播放/取帧/关闭，验证新鲜样本、存储释放和 binding 复用。本机 FFmpeg 因已有 x264 动态库缺失不可用，改用标准库生成夹具，未改本机依赖。
- UI 实际渲染使用真实 MainWindow、临时数据目录和 fake 通知服务，不读真实配置、历史或钥匙串；检查默认/最小尺寸、空态、正常、未确认、已确认持续、设置常规和微信结果态。README 只保留一张无个人信息的合成演示截图。此为 offscreen 检查，不代替 Retina/Windows 缩放/辅助功能实机验收。
- 安全门禁：白名单、符号链接和源码 ZIP 内容/CRC/哈希检查；固定 detect-secrets 1.5.0 脱敏扫描。仅允许一个按路径/类型/指纹精确匹配的既有合成响应标记，不整体排除 tests；无未批准命中。图片另人工查看。
- 构建链 Python 编译、shell 语法、YAML 与 actionlint **1.7.7** 通过；八类恶意 ZIP 与校验和篡改检查被拒。官方 runner/Action/Python/uv 依据见 `.github/DELIVERY.md`。

## 本地候选与待验

本地 Mac ARM64 原生候选已构建成功：`dist/VLCMonitor-0.4.0-macos-arm64-internal.zip`，附 UTF-8 basename SHA256 文件。静态检查 **139 个 Mach-O** 均含 ARM64；包内 Qt 平台插件、声音、许可证、manifest 和使用说明齐全，未捆绑外部 libVLC。原始 App 及解压后的 App 均通过 `codesign --verify --deep --strict`，签名为 **ad-hoc，未公证**。打包程序 `--diagnose` 返回版本 0.4.0、Python 3.12.13、VLC 3.0.21。这不代替打包 GUI 的目标设备验收。

独立 Git 仓库已初始化，审定清单暂存，未创建提交或配置远端；本地 manifest 如实为 `git_sha=null`、`working_tree_dirty=true`，CI 发布仍必须来自干净的标签提交。源码 ZIP 在最终内容冻结后独立生成，平台脚本不会各生成同名源码附件。原父目录 47 个迁移源文件最终 SHA256 全部保持不变。

收尾独立审查补齐两个交付门禁：校验和报告必须非空、无重复且精确覆盖预期 ZIP；Actions 附件名按 run_id 稳定，允许同一运行重跑 job 时替换临时 artifact，不覆盖已发布 Release。
